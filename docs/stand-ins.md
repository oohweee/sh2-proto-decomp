# Stand-ins for stripped code: where the original had room for code

Generated by `tools/standins.py`. A stand-in is a `__stripped_*` function: code the linker
dead-stripped, so none of it is in the binary. The constant-count stand-ins
(`static float __stripped_float_code_*`, `STRIPPED_DOUBLE_CODE()`) are fitted: they recreate a
compiler state that later functions need, their float-constant order or the software-double
register mode (see [toolchain.md](toolchain.md), "Root cause"). The other `__stripped_*`
functions (`config/stripped_functions.txt`) are reconstructions: some evidence says a
function stood there, but the body is a guess, and it leaves compiler state too. None is
recovered code. "Needed by" lists a stand-in's dependents: the functions that stop matching
when it alone is removed (`tools/standin_deps.py`, `config/standin_deps.txt`). They need not
be the function right after it.

The verdict checks the stand-in's own position against the original's line table. A
function the linker dead-stripped still takes up source lines, so where the gap before the
next function is at most 2 lines bigger than the file's usual gap between functions (no
room), **no code stood there**: the stand-in represents no code of the original at all. It
only reproduces a compiler state that the original's source produced in some other way,
not found yet. Its dependents are fake matches; `tools/progress.py` counts them separately.
Where the gap is at least 3 lines bigger (room), code could have stood there: the stand-in
is still not recovered code, and its dependents count as fitted, not fake.

Unknown: the file has too few functions to tell its usual gap between functions (fewer than
three gaps, or no gap size occurring twice), the next function isn't in the original's line
table, or the stand-in comes before the file's first function (the lines there hold its
declarations). `tools/progress.py` counts their dependents as fitted at an unknown position,
apart from those with room.

## Needed by several stand-ins together

Each file with more than one stand-in is also compiled with all of them removed at once. The
functions below still match without any one of them, but not without all: more than one
stand-in supports them. Which ones is not measured, so the verdict is "no room" only if every
stand-in in the file has no room, "room" only if every one has room, and "unknown" otherwise.
A stand-in listed above as needed by "nothing alone" in such a file may be one of those.
