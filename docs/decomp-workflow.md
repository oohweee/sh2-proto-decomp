# Decompiling a unit

A **unit** is one original source file, e.g. `DBG/dbalocate` (original `src\DBG\dbalocate.c`). Units
switch from asm to C whole: every function *and* the unit's data must match before it links. Every
game unit is C now; the same loop applies to reworking one (removing a stand-in, a fake match or an
original-code fallback).

Code style, comment markers (`Matching:`, `NON_MATCHING:`, `FAKEMATCH:`, `@bug`), header layout,
pragmas and the rules for inline assembly are in [STYLE.md](../STYLE.md). The compiler and the
build model are in [toolchain.md](toolchain.md).

## Tools

Run from the repository root in the build environment (Linux or WSL). From Git Bash on Windows,
`tools/wsl <command>` runs a command in WSL at the repo root.

| what | command |
|---|---|
| prototype, locals, struct layouts of a function | `python tools/dwarf1.py func <name>` (`--no-types` for just the signature) |
| a type / a global | `python tools/dwarf1.py type <name>` / `python tools/dwarf1.py var <name>` |
| the original's line table for a function | `python tools/dwarf_lines.py orig <function>` |
| the original asm of a unit (text + its data) | `asm/main/<unit>.s` (overlays: `asm/gx_<name>/<unit>.s`) |
| compile + compare a unit | `tools/wsl .venv/bin/python tools/diff_unit.py <unit>` |
| side-by-side for a function | `... diff_unit.py <unit> --show <func>` (or `--show-all`) |
| a modified copy of a unit | `... diff_unit.py <unit> --src <file.c>` |
| overlay unit | `... diff_unit.py gx_aee:Event/stage/stg_apart_e3fe` |
| how far each non-matching function is | `... tools/nonmatching.py` |
| statement layout vs the original's line table | `... diff_unit.py <unit> --lines`, `... tools/dwarf_lines.py layout <unit> <func>` |
| permuter directory for a function | `... tools/permute.py <unit> <func>` (see "Permuter" below) |
| float-constant stand-in search | `... tools/constcount.py <unit>` (see "Float-constant argument order") |

`diff_unit.py` compiles `src/<unit>.c` with the project flags (`configure.unit_cflags`: the global
flags plus the unit's `config/file_flags.txt` entry), prints per function `OK`/`XX` (`AS` for a
function linked from the original code), then simulates the link of every section from the unit's
original addresses. `LINKABLE` means the unit can go into `config/c_units.txt`. The build tracks
header dependencies (`tools/cdeps.py` writes a depfile per C object).

## Writing the C

- `#include "sh2.h"`: every struct/union/enum, global function prototype and global variable from
  the DWARF (`include/sh2/`, generated by `tools/gen_headers.py`; don't edit by hand). Anonymous
  structs are `anon_<size>_<hash>`; rename them in `config/type_names.txt` (with the evidence;
  names on thin evidence are marked provisional there). A wrong prototype goes in
  `config/prototype_overrides.txt` (which also takes `extern` lines).
- File-local things (static functions, static variables, local structs) are declared in the .c
  file itself. Library functions without DWARF (Sony's libraries, the C library, `libSh*`) are
  declared in the library headers (`include/sdk/`, `include/libc/`, `include/lib/`), never in the
  .c file: a missing declaration is added to the header (STYLE.md, "Headers").
- Use the DWARF names for parameters and locals. Order functions and data as in the original asm:
  the linker places them in file order.
- `long` is 64-bit. `u_long128` is the 128-bit quadword. `int` is 32-bit.
- Initialized data: copy values from the unit's `.data`/`.rodata` in the asm file. `diff_unit.py`
  compares data bytes, not just sizes.
- Read the original's line table before guessing: it records where each statement starts, so a
  statement boundary the original has and ours doesn't (or the reverse) is direct evidence about
  how the source was written.
- Write code the way the original programmers plausibly did (STYLE.md).

## Finishing a unit

1. `diff_unit.py` says `LINKABLE`.
2. Add `main <unit>` (or `gx_<name> <unit>`) to `config/c_units.txt`.
3. Full build: `tools/wsl .venv/bin/python configure.py` then `tools/wsl ninja`. All targets must
   print `OK`. `sh tools/check_all.sh` runs every check (lint, build, every unit, shift test,
   stand-in dependents, progress).

## Functions that don't match

A function whose C doesn't match is listed in `config/asm_functions.txt` and keeps its best
equivalent C, marked `NON_MATCHING:` with the remaining difference. `tools/asm_fallback.py` then
links the function's original code in its place, relocations included (other units' symbols by
name, this unit's data and functions section-relative), so the object stays relocatable.
`diff_unit.py` prints such functions as `AS`; `progress.py` counts them as linked, not matched. To
take a function off the list: make its C match, delete its line, rebuild.

The functions listed now are described in [nonmatching.md](nonmatching.md), with how far the
cause of each difference is known (most come from the compiler build, not the C);
`tools/nonmatching.py` measures how far each one's C is from the original.

### Permuter

[decomp-permuter](https://github.com/simonlindholm/decomp-permuter) tries random rewrites of a
function and keeps those that compile closer to the original. `tools/permute.py` sets it up from
our build (its own importer expects a Makefile project):

```sh
python3 tools/download_tools.py --permuter                        # once
tools/wsl .venv/bin/python tools/permute.py Event/event CharToFloat2
tools/wsl .venv/bin/python tools/decomp-permuter/permuter.py build/permuter/CharToFloat2 -j8
```

The rest of the unit is passed through verbatim (the function's codegen depends on what was
compiled before it), and `permute.py` checks that the permuter's rendering of the unit compiles
the function exactly as `src/` does before it writes the directory. It carries the unit's pragmas
along. Results land in `build/permuter/<function>/output-<score>-<n>/` (`diff.txt` is the change).
A score of 0 means the function matches, not that the change is right: it's usually a hint (which
statement order or temporary the compiler wanted) to turn into C someone could have written. Keep
implausible results only under the rules in STYLE.md (`FAKEMATCH`). The `missing terminating "
character` warnings come from the permuter's cpp pass over multi-line asm strings and are harmless.

### Optimizer settings and inline helpers

MWCC compiles a function without its global optimizer when the function contains native inline
assembly, and most helpers in `include/asm_helpers.h` / `asm_libm.h` (`sqr`, `itof`, `fabsf`...)
are native inline assembly. So when the original looks unoptimized (loads repeated after stores,
values recomputed, copies kept), test that first: copy the unit, wrap the function in
`#pragma push` / `#pragma global_optimizer off` / `#pragma pop` (or `opt_common_subs off`,
`opt_propagation off`) and run `diff_unit.py <unit> --src <copy>`. If it gets much closer, look for
an expression the original could have written with a helper (`x * x` as `sqr(x)`, an int-to-float
cast as `itof()`); a helper that matches is a better reconstruction than a pragma. Keep a pragma
only when it matches exactly and nothing plausible does (STYLE.md, "Pragmas"). An empty `asm {}`
block in the function is a quick version of the same test; it is a diagnostic, not source.

## MWCC 2.4 codegen and matching notes

Patterns observed while matching the game's functions with `mwcps2-2.4-001213` at
`-O2,p`. Most were found on one function and confirmed on others; where a rule is known to be
incomplete, it says so.

### Prologue, epilogue and constants in registers

- `jr ra` delay slots are never filled in compiled code ([toolchain.md](toolchain.md)).
- `ra` is saved with `sq`/`lq` (128-bit) in functions that call.
- Zero is materialized as `paddub rd, zero, zero` rather than `move rd, zero`.
- Small constants for `unsigned char` returns use `daddiu rd, zero, imm`.
- An early `return;` gives a jump to a `b epilogue`. An extra `return;` or a non-empty exit block
  explains a lone branch over `b end`. A redundant assignment of the value already in the
  register leaves its `b` (a branch that "jumps over nothing").

### Locals, stack and registers

- The DWARF lists a function's locals in *reverse* declaration order. Declare them in reverse of
  the `dwarf1.py` listing; the order drives stack slots and s-register choice (toolchain.md,
  "Register allocation", has the allocator's rules and the source levers that follow).
- `char` locals are sign-extended with `dsll32`/`dsra32`.
- **Unused parameters are missing from the DWARF** (e.g. a callee reading its pointer from `a2`).
  A static callee that takes and ignores such a parameter keeps that argument register busy in
  the caller, shifting the caller's register choice (the m3_* `EnemyXXXInit(this)` case): for an
  unexplained register shift before a call to a trivial static function, give the callee the
  missing parameter. A caller that passes an argument to a `(void)` static needs a K&R `f()`
  definition.
- Callers of trivial static functions in the same file keep `a0`–`a3`/`v1` live across the
  call, because MWCC knows what the callee clobbers.
- By-value struct parameters appear in the DWARF as locals; the callee copies from a pointer.
- Locals missing from the DWARF come from inline helpers (inlined locals and parameters have no
  DWARF): `Matrix_Scale`, `Vector_Zero`, `Float_Bits(f)` (`*(unsigned int *)&f` for GS packing),
  `Radian_To_Degree(x)`. Array locals missing from the DWARF are compound literals.
- **16-byte stack slots come from aligned typedefs.** The DWARF drops typedefs, but the game
  declared quadword pointers through `__attribute__((aligned(16)))` typedefs (`sceVu0FVECTOR`/
  `sceVu0FMATRIX`, and `Q_WORDDATA` for `union Q_WORDDATA`; `include/common.h`).
  MWCC gives a spilled or address-taken pointer to such a typedef a 16-byte-aligned slot at the
  *start* of the slot; a plain `union Q_WORDDATA *` gets a packed slot at its end. Replacing
  `union Q_WORDDATA *` with `Q_WORDDATA *` broke no function in 29 files and fixed 7. A spilled
  struct-pointer parameter in a 16-byte slot is a pointer to an aligned typedef of the struct; a
  spilled `float *` in one is an array parameter (`sceVu0FVECTOR origin`). `float (*)[4]` to
  `sceVu0FVECTOR *` is *not* safe wholesale: apply it per declaration where the stack shows it.
- **`volatile` is missing from the DWARF**: a reload right after a store, or a double load on
  `x++`, means the global was volatile (vblankCount, isUp, shHdWork). Declare it volatile locally.

### Software-double mode

Once MWCC has compiled any software-double operation (`dpadd`, `dpdiv`, a double compare, a double
literal such as `-750.0`) in a file, later functions stop using a0/a1 for temporaries and use a2
instead. This holds even when the double code is in a dead-stripped function. If an original
keeps a parameter in a0 and puts temporaries in a2, look for double code (or a stripped function
that had some) earlier in the file: m3_play_2d's `upper_walk_2d` matches only because
`PlayerChangeAngleToCameraY` precedes it. A probe double function placed after the includes of
every unfinished unit fixed 9 functions, broke none of 60 matched units tested, and broke only
functions *before* where the original's double code must have been (en_pap: InitData fixed,
AnimeSet broken, so it sat between them). `STRIPPED_DOUBLE_CODE()` (`include/common.h`) is that
probe as a fitted stand-in, removed by `tools/mwcc_fixup.py`; whether the original had room for
code at its position is in [stand-ins.md](stand-ins.md). For an unexplained "a0 where the original
has a2" register diff, try it first.

### Data

- `.data` objects come out in declaration order. Function-local initialized statics are emitted
  when their function is compiled.
- `.bss`: explicitly zero-initialized objects (`= 0`, `= NULL`; file and function statics) in
  source order, ahead of the rest; zero-initializer templates (`@N`) when their function is
  compiled; the remaining uninitialized statics and globals at the end of the file, in reverse
  order of definition (so where a static is *defined* matters).
- Every data object is 8-aligned, 16-aligned from 16 bytes up (toolchain.md, "Data alignment").
  DMA/GS packet buffers are often `__attribute__((aligned(64)))` or `(128)`; `diff_unit.py`
  reports "would link at X" when an object needs more alignment.
- Tables in `.rodata` are `static const`. A non-zero local array initializer is copied (`lq`/`sq`)
  from an anonymous `.data` object; an all-zero one from an anonymous `.bss` object. Compound
  literals work the same way: `v = (struct FVEC){0, 0, 0, 0};` gives the anonymous 16-byte `.bss`
  template and an lq/sq copy (`FVEC` is the name `config/type_names.txt` gives the anonymous
  four-float struct).
- File statics without DWARF take the splitter's name minus `_XXXXXXXX` (`d`).
- String literals go to `.rodata`, one section each, 8-aligned. Trailing `.asciz ""` entries in
  `.rodata` are alignment padding between string sections.
- Float constants the compiler can't build with `lui` become `@N` literals in `.rodata`. Write
  every digit of a constant: `7.65f` isn't `7.6499996f`.

### Asserts and log strings

- Asserts bake `"<file>:<line>"` into the format string:
  `printf("<file>:<line>> assert:(%s)\n", #x); while (1) {}`. Use `assert()` (bare `if`) or
  `assert_dw()` (`do { } while (0)`) from `common.h`, whichever matches, and put it on the
  original line (a commented `#line N` where our source is shorter; STYLE.md).
- The original stringizes the macro-*expanded* expression; write it out expanded. An assert string
  showing `Name(x)` unexpanded means `Name` was an inline function.
- Log/verbose strings bake `"<file>:<line>> "` into each line.

### Branches and compares

- `c ? a : b` leaves a jump-to-jump join; if/else doesn't.
- `x != K` vs `x == K` decides which body comes first. `if (x != -1) {...} else return 0;`
  differs from an early return.
- `x > K` / `x <= K` put the `slt(i)` result in `$at`; `x >= K` / `x < K` use a value register
  (`if (v > 9)` gives `slti $at, v, 10`).
- `0 <= x && x < N` gives `slt/bnez`; `x >= 0` gives `bltz`. `a == 2 || a == 3` becomes an
  `addiu; sltiu` range check.
- `(x & 1) ? 0 : 1` gives `movz`; `!(x & 1)` gives `sltu/xori`. `!c` on an `unsigned short` adds
  an `andi` copy that `c == 0` doesn't.
- Float: `if (f)` gives `c.eq f,0`; `f != 0.0f` gives `c.eq 0,f`. `x = (x > K) ? K : x` is the
  jump-free clamp; nested ternary clamps give the jump-to-join. `((a > PI) != 0) ? ... : ...`
  materializes the boolean.

### switch

- Few cases: a `beq` chain that tests the cases in reverse source order; bodies are laid out in
  source order, and `default` can come first.
- Jump tables cover every value up to the highest case; they come from listing every case
  (empty `case N:` entries), not from the default.
- `switch (x) { case 0: ... }` gives `beqz case; b end`, which an `if` doesn't.
- `switch (char)` with negative cases gives `addi` + jump table (splat marks such a function as
  hand-written; it isn't).
- MWCC reuses a constant left in a register by the compare chain: an odd store value from a
  never-loaded register is that constant.

### Loops

- A `for` increment is followed by a `nop` before the condition label; `while` isn't.
  `*pos++ = pos[5];` avoids that loop-end nop; an inline call in the body adds it.
- `for (k = f(); k != -1; k = f())` calls `f` twice in the code; `while ((k = f()) != -1)` once.
- An increment laid out before the loop body comes from the comma form `for (...; i++, p = q)`.
- `while (1) { if (!c) break; ... }` tests at the top; `while (c)` at the bottom.
- `i = 0; do {...} while (++i < N);` has no initial jump.
- `do { } while (0)` macros (`EN_SET_LEVEL`, `EV_STEP`) leave one `nop` where they end a body that
  falls into a join, a `case` label or the epilogue. The original was inconsistent: check each
  site. The allocator also treats them as loops (toolchain.md, "Register allocation").

### Calls and evaluation order

- `lui/addiu + jalr` is a call through a cast function pointer (`((int (*)(int))fn)(x)`).
- An argument with an explicit cast (`(float)`, `(int)`, `(float (*)[4])&mat`, `(float *)&pos`,
  `(void *)arr`) is evaluated before the others, and before float-constant loads. Unconverted
  arguments follow in parameter order; implicit conversions (e.g. to `void *`) come after the
  float constants.
- **Calls without a prototype.** Some original files called a function with no prototype in scope,
  or with extra arguments. A block-scope `void f();` reproduces that: arguments unconverted
  (`float` promoted to double), evaluated last to first, and no argument copies (a call with no
  `paddub a0, s0` went through such a declaration with the value still in `a0`). Where `sh2.h`
  already declares `f` (a game function), a `local f <unit> <reason>` line in
  `config/prototype_overrides.txt` makes `tools/gen_headers.py` wrap its prototype in
  `#ifndef SH2_LOCAL_f`; the file then defines `SH2_LOCAL_f` before `#include "sh2.h"` and
  declares `void f();` itself, with a `Matching:` comment (src/Chacter/m3_maria_sub.c does this
  for `GameMariaDamagedCountUp`; STYLE.md, "Headers").
- Inline call arguments are evaluated last to first, and inline calls inside an expression before
  the rest of it. `static inline` getters load their global before the other compare operand;
  stores inside an inline load the pointer before the value. A static inline function and a macro
  with the same body give different evaluation order and registers (DmaAddr, PK_ADD).
- In `a = b = v`, `b` is stored first. A 64-bit multiply calls `__muldi3`.

### Float arithmetic

- `a*a + b*b` always fuses into `mula`/`madd` at every -O level; unfused originals were written
  as separate statements (`d = x*x; d += z*z;`).
- `1.0f * x` left unfolded means the 1.0 came from a variable.
- `unsigned short` to float: some files converted through `int` (an `(int)` cast).

### Integer constants

- A large constant that appears twice is CSE'd into a register; the original often wrote such
  constants as expressions (`sizeof(...)/sizeof(...)`).
- The same int mask constant used twice is built with `lui/ori/and` at the first use; used once,
  with `dsll32/dsrl32`.
- `x ^ -1` becomes `nor`. An `xor` with -1 held in a register comes from an unsigned constant used
  more than once (`x ^ 0xFFFFFFFF`, key_conf) or from `v = -1; v ^= x`.

### Float-constant argument order

Which float-constant argument of a call is materialized first depends on leftovers of earlier
functions' syntax trees in the compiler's memory (toolchain.md, "Root cause"). Options, in order
of preference: spellings the original's line table supports; a choice between spellings that
compile identically, listed in `config/order_fits.txt` (STYLE.md, "Comments"); a fitted stand-in.
`tools/constcount.py <unit>` searches for a stand-in (`--apply` rewrites the file; `--max` raises
the constant limit above 24). A stand-in is fitted, never recovered, and where the original's
line table shows no code stood, its dependents count as fake matches ([stand-ins.md](stand-ins.md)).
A propagated `static const float k = 8.0f;` argument can also reorder float constants (not
general).

### Inline assembly

Allowed where the original clearly used it (STYLE.md, "Inline assembly").

- **Native `asm { }` blocks are never optimized, and they switch off the global optimizer for
  the whole function** (scheduling, register choice, CSE, dead-code elimination, constant
  propagation), including a block inlined from a helper. GCC-style `__asm__` (even
  `__volatile__`) is scheduled and optimized around: loads feeding it are CSE'd, repeated `lwc1`
  become `mov.s`. So the helper's form matters as much as its instructions.
- GCC-style asm evaluates operands in operand-list order; native inline calls evaluate their
  arguments last to first. `"+f"` works for in-place GCC asm operands (`"0"` doesn't).
- In native blocks, register names win over C names, so a C variable called `v0` or `a1` can only
  be used as a `%N` operand in GCC-style asm.
- Asm written in the function body gives a line-table entry per instruction; asm from an inline
  helper doesn't. The original's line table tells the two apart.
- Instruction patterns that mean an asm helper (`include/asm_helpers.h`, `asm_libm.h`):
  - in-place `mtc1 rX,fN; nop; cvt.s.w fN,fN` (or `lwc1 fN; cvt.s.w fN,fN`): `itof`;
  - `cvt.w.s; mfc1` with no `fptosi` call: `ftoi`;
  - `sqrt.s` / `rsqrt.s` (a plain `sqrtf()` is a `jal`);
  - `abs.s`: `fabsf`; `min.s`/`max.s`; `max.s; nop; min.s`: a GCC-style `fclamp(x, lo, hi)`;
  - `slt t7; movn` clamps; `sync.l`; `break` as `.word 0xD`; Sony's `ExitHandler()` (`sync.l; ei`);
  - `mfc1` of a constant (`move r, zero; nop`, `lui r, 0x3F80`): `fbits()`, the float's bits;
  - VU0 `itof4`: `qmtc2.ni i,vf4; vitof4.x vf4,vf4; qmfc2.ni t7,vf4; mtc1 t7,r`; `ftoi4`
    (`vftoi4.x`);
  - `lq t7 / sq t7` vector copy (in about 70 files):
    `inline void vcopy(void *s, void *d) { asm { lq t7,0(s); sq t7,0(d) } }` (4x4 matrix: `lq
    t6/t7` pairs).

  Use a helper only where the original's instructions show it. `asm_libm.h` defines `fabsf`,
  `fmaxf` and `fminf` as inline asm, so a file that calls the library `fabsf` (`jal fabsf`)
  doesn't include it.
- **Hand-written functions** (splat marks them; e.g. everything in `SH2_common/sh_vu0`) lose their
  parameters in the DWARF; prototypes come from `config/prototype_overrides.txt`. Write them as
  `asm <ret> f(<params>) { .set noreorder ... jr ra; <delay> }`, or as a C function whose body is
  an `asm { }` block using `a0`/`a1`... directly (MWCC then inserts branch-delay nops itself).
  Inline `asm { .set noreorder ... }` blocks must end with `.set reorder`. `vclipw` is written as
  `.word`.

#### VU0 macro-mode code (COP2: lqc2/sqc2, vadd, vmul, vopmula, qmfc2...)

MWCC 2.4 accepts **GCC-style extended asm**. The game's helper headers
(`sh_vu0.h`, `fi_libvu0_inline.h`) were `static inline` functions written this way. Write the asm as
one multi-line string (adjacent string concatenation isn't supported), mnemonics without `$`:
```c
static inline void _shNormalize(float *v0, float *v1) {
    __asm__ __volatile__("
    lqc2      vf4, 0x0(%1)
    vmul.xyz  vf5, vf4, vf4
    vaddy.x   vf5, vf5, vf5y
    vaddz.x   vf5, vf5, vf5z
    vrsqrt    Q, vf0w, vf5x
    vwaitq
    vmulq.xyz vf4, vf4, Q
    sqc2      vf4, 0x0(%0)
    " : : "r"(v0), "r"(v1));
}
```
- Operands land in free registers (a pointer already in `aN` stays; `&g.field` gets `addiu v1`).
- Out-of-line copies of the helpers exist (`_shAddVector`, `_shScaleVector`, `_shNormalize`,
  `_shOuterProduct`, `_shLength`, `_sceVu0ApplyMatrix_1`, `_sceVu0Normalize`, `_sceVu0RotTransPers`):
  their code gives each helper's exact body. Where the copies come from and how to reproduce
  them: [headers.md](headers.md), section 4.

### Dead-stripped functions

Symptom: an assert or format string sits earlier in `.rodata` than its only user, or `.bss` has a
zero-initializer template no surviving function uses. The Metrowerks linker removed a function
nothing called; its string literals that another function shares stay where it first emitted them
(strings only it used went too), and `.bss` isn't stripped. Write the function (name and body
guessed; stripped functions have no DWARF) and list it in `config/stripped_functions.txt`;
`tools/mwcc_fixup.py` empties it and its private data (examples: mc, clani, light_n, anime).
toolchain.md, "Dead-stripping", has the build side.

### What the relocation check catches

`diff_unit.py` resolves every relocation and compares the result with the original binary, and a
pointer in our data where the original has none is an error. This finds behaviour bugs that
identical code bytes hide: a swapped `case 1`/`case 2` pair in anime's shExec (only the jump table
differed) and a NULL-vs-function-pointer table entry. After a function's code matches, check the
unit again.
